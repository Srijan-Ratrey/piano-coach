# The browser app

The wait-mode piano-roll: falling note bars that stop at the keyboard line and
wait until you play them on a real piano.

```bash
npm install
npm test        # 21 tests — must pass before trusting anything below
npm run dev     # http://localhost:5173
```

`localhost` is not a convenience: `getUserMedia` is blocked on plain HTTP
everywhere except localhost, so a plain LAN IP will silently fail to get the
microphone. Testing on a phone needs HTTPS.

---

## `npm test` is the load-bearing part

Two suites, and they check different things.

**`test/golden.test.js`** — does this JS reproduce the Python reference?
Vectors come from `uv run python -m spike.export_golden`. This is what makes
the two-language split honest (DECISION #16): the spike's tuned thresholds are
only meaningful alongside the exact transform that produced them, so a port
that drifts turns the spike's measurement into fiction. It checks the periodic
Hann window, equal-tempered pitch, the band table bin-by-bin, chroma over
embedded audio frames to 1e-6, and both state machines step by step.

**`test/session.test.js`** — does the wiring work? Synthetic piano audio is fed
through the real `WaitModeSession`; playing the right notes must advance the
step, wrong notes and silence must not. A correct verifier handed the wrong
target is still a broken app, and only this suite catches that.

## Layout

```
src/audio/     the port of spike/core — ALGORITHM.md is the spec
  params.js      constants; do not edit without re-running the Python sweep
  dsp.js         periodic Hann + radix-2 FFT, unscaled, matching numpy.rfft
  chroma.js      band table -> per-note energies -> 12-bin chroma
  onset.js       spectral flux, adaptive median, warm-up and refractory gates
  verify.js      the four-condition state machine
  pipeline.js    Analyser + the sliding analysis window
  mic.js         getUserMedia, AudioContext, worklet plumbing
src/song/      MIDI parsing, step grouping, hands, fingering heuristic
src/render/    Canvas piano-roll and keyboard geometry (keys along the bottom)
src/session/   the wait-mode loop
public/capture-worklet.js   served verbatim — see below
public/midi/   sample songs, generated by tools/make_sample_midi.py
```

## Things that will bite whoever touches this next

**The worklet lives in `public/`, not `src/`.** Importing it with `?url` looks
tidier, but Vite inlines files under 4 KB as a `data:` URL and
`audioWorklet.addModule()` accepts those inconsistently across browsers. A real
URL always works. The worklet must therefore stay dependency-free.

**Not `AnalyserNode`.** It applies its own smoothing and dB conversion and does
not expose its windowing, so it cannot reproduce the golden vectors.
`smoothingTimeConstant = 0` is necessary but not sufficient. The worklet hands
over raw samples and we run our own FFT.

**The three mic flags are off deliberately.** `echoCancellation`,
`noiseSuppression` and `autoGainControl` all default to on, and all three
damage a sustained piano note. AGC is the worst: it changes the balance between
partials over time rather than scaling them equally, which defeats exactly the
loudness-independence the L1-normalised chroma is built on.

**Sample rate is read from the AudioContext, never assumed.** It is usually
48 kHz on macOS but is not guaranteed. The band table is rebuilt from the real
rate; assuming 48000 mistunes every note.

**The onset detector is not reset when a step advances.** Its flux history
describes the audio stream, not the step. Clearing it per step would put the
detector back into warm-up at every step of a song — the state in which room
noise reads as a strike.

**`@tonejs/midi` is imported through a namespace.** It ships ESM under
`module` and CommonJS under `main` with no `exports` map, so Vite and bare Node
resolve different files. The namespace form works under both, which is what
lets the session tests run headless.

## Modes and the one clock

Song time advances at a constant rate scaled by tempo (25–150%, default 100%,
persisted in `localStorage`). The two modes are the same mechanism with one
conditional clamp:

```
songTime += dt * tempo
WAIT:  songTime = min(songTime, currentStep.time)   // freeze at the line
PLAY:  unclamped; notes pass whether or not they were played
```

Deliberately not two code paths — two clocks would drift apart the first time
either was touched. WAIT is the default and still advances only on a confirmed
match (DECISION #8); PLAY is opt-in, gates nothing, and reports misses as
feedback only.

**The session owns the clock, not the renderer.** `PianoRoll.setScroll()` is
fed `session.songTime` each frame and tracks it exactly. This matters: the
renderer used to ease toward the next step with a fixed time constant, so every
transition took ~270 ms whether the gap was a sixteenth or a whole note, and
the motion carried no rhythm. Pacing is a property of the music, so it lives
next to the step logic.

`main.js` clamps `dt` to 50 ms. Not cosmetic — `requestAnimationFrame` stops in
a background tab, so the first frame back reports the entire absence and would
otherwise jump the song clock by that much.

A miss flashes the **keys**, not the bar. A step is only declared missed a
grace period after it crosses the line, by which point its bar is mostly
clipped under the keyboard; the keys are stationary and already where the
player is looking.

## Deep links

`?song=<slug>&hand=right|left|both&mode=wait|play&tempo=<25-150>` opens straight
into the roll — for example `/?song=ode-to-joy&hand=right&mode=play&tempo=75`.

It always starts the **no-microphone** mode. A page cannot open the microphone
without a user gesture, so the link shows the roll and you press the button
yourself if you want to be listened to.

## Current state

The detection thresholds are the spike's untuned defaults. Until a corpus has
been recorded and `spike/RESULTS.md` has numbers in it, treat how the mic mode
*feels* as unmeasured — if it seems unresponsive or trigger-happy, that is as
likely to be the tuning as the algorithm, and the corpus is what tells the two
apart.

Not built yet: tempo control, section loops as UI, per-hand difficulty
thinning, the library screen, playback of passed notes, and PWA packaging.
